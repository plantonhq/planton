# Kubernetes object store + vector database: SeaweedFS + Qdrant — two new kinds at full depth; Rook Ceph retired

## What changed

- **KubernetesSeaweedFs (923, new)** — the catalog's in-cluster
  S3-compatible object store, installed from the official SeaweedFS Helm
  chart pinned to 4.40.0 (Apache-2.0). Typed master/volume/filer tiers
  whose data volumes are all mapped to PersistentVolumeClaims (the
  chart's out-of-the-box hostPath storage is bare-metal grain; the
  escape hatch can restore it), S3 on by default with chart-owned stable
  credentials (`<name>-s3-secret`, generated by the chart's lookup-based
  hook and kept across upgrades), typed buckets created by the chart's
  install hook (TTL, versioning, object-lock, anonymous-read arms, with
  S3 bucket-naming rules mirrored in validation), an
  embedded-or-dedicated S3 gateway arm, the XYZ replication-code
  vocabulary taught on the field, and an admin console that is never
  exposed unauthenticated (module-generated `<name>-admin-auth`
  credentials). The import catalog gained its first `random_password`
  entry — the import ID is the password value read from the materialized
  Secret, with the generation-shape arguments declared config-only.

- **KubernetesQdrant (924, new)** — the catalog's vector database,
  installed from the official Qdrant Helm chart pinned to 1.18.2
  (Apache-2.0; no CRDs). An always-on Raft cluster scaled by replica
  count, chart-owned API keys (a generate arm using the chart's own
  lookup-stable Secret, and an existing-Secret arm read at template
  time; declaring a read-only key requires the read-write key — the
  CRD-less service enforces nothing itself), TLS from a certificate
  Secret (probes switch scheme with the listener; the `-unprivileged`
  image variant is a tag suffix on the same repository), dual
  persistence (storage plus an optional snapshots volume), and typed
  scheduling with the anti-affinity recipe documented.

- **Rook Ceph retired** — the `KubernetesRookCephOperator` and
  `KubernetesRookCephCluster` kinds are removed from the catalog. Ceph
  OSDs require raw block devices/partitions and monitor quorums —
  datacenter-grade machinery with no honest single-node proof; the
  in-cluster object role is served by SeaweedFS. The enum slots were
  reassigned to the two new kinds.

- **E2E surface (authored and compiled; live proving runs separately)**:
  dedicated verifiers — SeaweedFS (tier readiness, declared buckets
  asserted via ListBuckets, a live S3 put/get round-trip with the
  chart-generated credentials, and a durability arm that deletes the
  volume-server pod and re-reads the object byte-identically) and Qdrant
  (a live vector round-trip: collection create, upsert, similarity
  search asserting the nearest neighbour, every request carrying the
  read-write key when auth is on, and a persistence arm that deletes pod
  zero and re-runs the search) — plus six scenarios and import maps for
  both kinds. Profiles ship as `pending_proof`.

## Validation

Spec tests for both kinds (every CEL rule accept+reject locked); offline
`tofu` plan and `pulumi preview` proofs across full-surface and minimal
shapes for all four modules (the minimal-shape preview caught and fixed
a nil-dereference on an absent optional block); secret-coverage,
reference, containment, import-map and outputs conformance gates;
image pullability probes at the exact pinned tags; repo-wide Bazel
build; e2e-build/e2e-vet; license footers; all presets and scenario
manifests CLI-validated.
