# The platform downloads official modules at its own catalog release, and the operator stops naming one

**Date**: September 16, 2026
**Type**: Architecture / Bug fix
**Components**: `operator/internal/resources/control_plane.go`, `operator/internal/platformversion/platformversion.go`, `operator/api/v1/planton_platform_types.go` (and the regenerated CRD in `operator/config/crd/bases/` and `helm/planton-operator/templates/crds/`), `operator/internal/resources/testdata/boot-contract.txt`, `catalog/kubernetes/kubernetesplantonplatform/v1alpha1/spec.proto` (and its stubs, `reference.md`, `pkg/protodocs/index.json.gz`), `catalog/kubernetes/kubernetesplantonplatform/iac/tf/`, `catalog/kubernetes/kubernetesplantonplatform/iac/pulumi/module/platform_cr.go`, `catalog/auth0/auth0client/iac/tf/`

## Summary

A self-hosted platform validates manifests against the catalog release its build vendored, seeds that release's chart bundle -- and downloaded official IaC modules from a *different* release: the one the operator compiled in as `controlPlaneModuleArtifactsVersion` and handed to the control plane as `PLANTON_VERSION`. The constant sat at `v0.5.33` while the platform's own catalog pin was `v0.5.55` and then `v0.5.60`, so a kind the platform's schemas accepted (`KubernetesCnpgBarmanCloudPlugin`, born in `v0.5.56`) failed at deploy with an HTTP 404 on a module URL carrying a version the adopter never chose and could not change: the CR's `iacModulesVersion` override existed, but the catalog kind `KubernetesPlantonPlatform` did not expose it, and the only remedy was a new operator image.

The version is gone. The operator no longer renders a module version at all: the control plane resolves official modules at its own embedded catalog release -- the same pin its schemas and chart bundle come from, the same rule the CLI's and the desktop's Go engine already followed -- so a platform release knows exactly one catalog release and every module a kind it accepts is published there. The CR's `spec.controlPlane.iacModulesVersion` survives for the one situation it exists for, a retracted artifact set, rendered by presence under Spring's relaxed-binding name `PLANTON_INFRAHUB_IACMODULES_VERSION` (hyphens stripped, exactly as `PLANTON_BOOTSTRAP_INFRACHARTS_ENABLED`), and `KubernetesPlantonPlatform.spec.controlPlane.iacModulesVersion` now carries it through both engines, pattern-validated to an exact release tag and ignored when unset.

The platform floor moves to `v0.0.65`: an older control plane binds `PLANTON_VERSION` without a default and cannot boot once the operator stops rendering it. The boot-contract fixture records the renamed variable and the new floor. The platform's own side of the contract (the oldest operator that serves it) does not move -- a control plane at or past the floor runs correctly under the previous operator, ignoring the variable it renders.

Alongside, the `auth0client` OpenTofu module sends `allow_any_organization` on a client grant only when the manifest sets it true, matching the Pulumi module. Auth0 reads the attribute's presence as use of Organizations for machine-to-machine access, a paid feature, and refused every grant on a tenant without it ("Please upgrade your subscription to use Machine to Machine access to Organizations") -- for a feature the manifest never asked for.
