# Two generated records on main catch up with the code they describe

**Date**: September 15, 2026
**Type**: Chore
**Components**: The preset-validity gate's baseline; the KubernetesOpenBao Pulumi module's Bazel target

## Summary

Two records that a generator or a gate owns had fallen behind the code on `main`, and each has been red or stale since the change that outran it. The preset-validity baseline still listed the Vertex AI endpoint's private-PSC preset as a known-invalid preset after the preset was fixed, so the gate failed on every commit since September 14 with the sentence "stale baseline entry, remove it from baseline.yaml"; the row is removed and the gate is green again. The OpenBao Pulumi module's `BUILD.bazel` had never been regenerated after the module gained its backup, restore, and scripts sources, so Bazel's view of the module was missing three files and two dependencies; the target is what `gazelle` emits for the module as it stands.

## What Changed

- `pkg/presetvalidity/baseline.yaml`: the `gcpvertexaiendpoint/presets/03-private-psc.yaml` row is gone. The gate says exactly this when a baselined preset becomes valid; the fix is the one it prescribes.
- `catalog/kubernetes/kubernetesopenbao/iac/pulumi/module/BUILD.bazel`: `backup.go`, `restore.go`, and `scripts.go` join `srcs`; the R2 helper package and the Kubernetes batch SDK join `deps`. Generated by `gazelle`, not edited.

## Why

A generated record that disagrees with its source is a lie the next reader has to discover. Both were found by running the repository's own lanes on `main` before a release -- the full proto generation lane (which runs `gazelle`) and the preset-validity gate -- and neither has anything to do with the release's content. They are fixed on `main` so the release is cut from a tree whose gates and build graph tell the truth.

## Verification

- `go test ./pkg/presetvalidity/` green (it was red with the one stale-row sentence before the change).
- `make protos` on `main` leaves the tree clean apart from this `BUILD.bazel`, which is the lane's own output.
