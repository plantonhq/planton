# The provider sends a manual instance count under AUTOMATIC worker pool scaling

**Area**: `catalog/gcp/gcpcloudrunworkerpool`, upstream `google_cloud_run_v2_worker_pool` (both the Google provider and the beta provider Pulumi bridges).
**Type**: bug, upstream.

## What a platform engineer sees

A worker pool with `scaling.scalingMode: AUTOMATIC` can't be created: the provider always sends `scaling.manualInstanceCount` (0 when unset), and Cloud Run refuses any manual count under AUTOMATIC: `Error 400: Violation in CreateWorkerPoolRequest.worker_pool.scaling.manual_instance_count: scaling mode must be set to MANUAL.`

## What Google accepts (measured 2026-11-21, `validateOnly` creates)

- AUTOMATIC with `launchStage: BETA`, min 1 and max 2, and no `manualInstanceCount`: accepted.
- The same request with `manualInstanceCount: 0`: refused with the 400 above.
- AUTOMATIC without `launchStage: BETA`: refused, `FAILED_PRECONDITION` ("The feature 'Automatic scaling mode' is not supported in the declared launch stage ... should be specified at least as BETA").

So the provider's count is the only thing standing between the spec and a working AUTOMATIC pool, once the launch stage is BETA. The provider still sends it unconditionally in v8.12.0 (`expandCloudRunV2WorkerPoolScalingManualInstanceCount`, no empty-value guard).

## What the catalog does

The spec refuses AUTOMATIC with that reason (`scaling.automatic_not_deployable`); MANUAL pools deploy. The bounds stay modeled because Google's API offers them.

## Fix

Report it upstream (the provider should send the count only in MANUAL mode). Once the pinned provider does, the CEL rule becomes "AUTOMATIC needs `launch_stage` BETA or ALPHA", and the GUIDE, README, catalog page and an AUTOMATIC scenario return.
