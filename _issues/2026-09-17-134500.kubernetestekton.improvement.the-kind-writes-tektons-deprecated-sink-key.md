# `KubernetesTekton` writes Tekton's deprecated CloudEvents sink key; the current one is `config-events`

**Area**: catalog kind `KubernetesTekton` (`catalog/kubernetes/kubernetestekton/iac/tf/locals.tf`, `iac/pulumi/module/tekton_config.go`)
**Type**: improvement (found 2026-09-17 while reading Tekton's current documentation for the build path's event transport; nothing is broken today)

## What the kind does

`pipeline.cloud_events_sink_url`, when set, is rendered into the `TektonConfig` as the `default-cloud-events-sink` key of the `config-defaults` ConfigMap (`locals.tf:122`, `tekton_config.go:120`).

## What Tekton says

Tekton Pipelines deprecated `default-cloud-events-sink` in `config-defaults` in v0.50 in favor of a dedicated `config-events` ConfigMap (`sink`, `formats`); the deprecation table names it for removal, and the current docs call the old key "still available, but deprecated, and will be removed". Since v1.13 CloudEvents are sent by a separate `tekton-events-controller`, which reads `config-events`. Sources: tekton.dev/docs/pipelines/additional-configs ("Configuring CloudEvents notifications"), tekton.dev/docs/pipelines/deprecations, TEP-0137.

## Why it still matters after Planton's runners stopped needing a sink

From platform `v0.0.70` Planton's build-capable runners watch their own build namespace's PipelineRuns and TaskRuns and need no sink, so the estate leaves this field unset. The field stays for adopters with an event consumer of their own -- and for them the kind writes a key Tekton has announced it will remove.

## Expected

- The kind renders the sink into `config-events` (`sink`, and `formats: tektonv1`) through the `TektonConfig`'s pipeline options, or documents which Tekton Operator versions carry that ConfigMap and falls back to the old key only below them.
- The kind's README and `catalog.md` name the ConfigMap the value lands in.
