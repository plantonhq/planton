# A GCP resource without `project_id` fails only at deployment

**Area**: every GCP kind with a `project_id`
**Type**: bug. Handed by the burn-down of every reported issue (2026-09-27, F19, the founder's report).

## What a platform engineer sees

A GCP manifest that leaves `project_id` unset passes `chart validate`, `chart build` and the dry run, and fails only when the deployment runs, because no default project reaches the module.

## Fix (agreed with the founder)

Every GCP kind's `project_id` becomes required, a literal or a `GcpProject` reference, so validation refuses it offline with the server's sentence. Remove the catalog and module sentences that promise a provider default project.
