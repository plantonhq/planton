# The projection drops a field whose reference is still unresolved, instead of failing

**Area**: `pkg/iac/specprojection` (the projection every Terraform module's tfvars and every Kubernetes mirror object is built from), on both engines
**Type**: bug (silent data loss on a path that should be impossible, but is not guarded)

## What a platform engineer would see

A manifest whose reference (`valueFrom`) reaches a module still unresolved deploys without the field:

- **A singular field** is deleted from the map (`flattenSingularField`).
- **A list element** becomes `null` (`flattenListField`).
- **A map entry** is deleted (`flattenMapField`).

No error is raised. Downstream, the provider or the API server sees a spec with a hole. For a Kubernetes mirror kind that can be worse than an error: a ServiceMonitor whose Secret selector lost its `name` reaches prometheus-operator, which skips the whole monitor and says so only in its own log.

## Why it rarely happens today

The platform and the CLI resolve every reference before a module runs (`pkg/manifestgraph.ResolveRefs`), and an unresolved reference becomes a finding that stops the deploy first. So the projection's "should have been resolved" comment is true on the main paths. Nothing enforces it, though:

- the e2e runner documents that "the pulumi modules drop" an unresolved reference;
- not every caller of `specprojection.Project` / `ProtoToTFVars` has been traced to confirm it resolves first.

## What would make it right

- `ExtractValue` errors (today only an unresolved `StringValueOrRef`) propagate out of `Flatten`/`Project` as an error naming the field path, on both key styles.
- Every caller handles the error: the tfvars writers, `manifestprojection.Render`, the variables and module generators, and the e2e harness.
- A test pins it: projecting a manifest with an unresolved reference fails and names the field.

This touches every kind's projection, so it is its own change, with a plan. The two Kubernetes shape markers (`kubernetes_int_or_string`, `kubernetes_list_valued_map`) introduce no drop path: their placement is guarded, so a malformed value cannot reach them.
