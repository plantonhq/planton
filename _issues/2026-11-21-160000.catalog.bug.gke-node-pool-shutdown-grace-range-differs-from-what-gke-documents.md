# The GKE node pool's shutdown grace range differs from what GKE documents

**Area**: `catalog/gcp/gcpgkenodepool/v1alpha1/spec.proto`, `kubelet_config.shutdown_grace_period_seconds` and `shutdown_grace_period_critical_pods_seconds`.
**Type**: bug.

## What a platform engineer sees

The spec accepts a shutdown grace period from 10 to 10000 seconds. GKE's node system configuration guide ("Graceful termination of Spot VMs in GKE") lists only 0, 30 and 120 as accepted values, with 30 the default and 15 the critical-pods default, on control planes at 1.35.0-gke.1171000 or later. So the spec refuses 0, which GKE documents, and accepts values such as 60 or 600 that GKE may refuse at apply.

## What is known

A live run (2026-11-20) proved 120 and 30 round-trip on a Spot pool on both engines. No run has tried 0 or a value outside GKE's documented set.

## The behaviour wanted

The rule matches what GKE accepts, measured: one live arm per boundary (0, and a value outside the documented set) settles whether the API enforces the documented set or the wider range, and the CEL follows it.
