# A Private Service Connect forwarding rule pulls the global load balancer chain as its prerequisites

**Area**: `shared/catalogkind/catalog_kind.proto` (`GcpGlobalForwardingRule`'s `prerequisites`), and every consumer of a kind's registry prerequisites.
**Type**: bug.

## What a platform engineer sees

`GcpGlobalForwardingRule` models every forwarding-rule form: the global external load balancer's frontend, a regional rule, and the Private Service Connect consumer rule (scheme NONE, a service attachment as target). The registry lists `GcpTargetHttpsProxy` and `GcpGlobalAddress` as its prerequisites, which is true only of the global HTTPS frontend.

Whatever reads those prerequisites treats a PSC consumer rule as needing a target HTTPS proxy, its URL map, backend service, SSL certificate and a global address. A Redis Cluster endpoint set's two PSC rules therefore pull in two whole global load balancer chains they never use.

## Fix

A kind whose prerequisites depend on its form needs prerequisites by form, or none listed. The registry's `prerequisites` can't express a form today. Either the forwarding rule lists none (its forms share no prerequisite), or the registry gains a way to name prerequisites per form, and every reader (the e2e dependency resolver, the console's create flow) follows it.
