# A GCP Private CA pool has no iam_members companion

**Area:** the open-source GCP catalog (`catalog/gcp/`), `GcpPrivateCaPool`.
**Confidence:** read from the spec; the parity doctrine gives every resource with an IAM policy an `iam_members` companion, and this one has none.

## What happens

A platform engineer who wants a principal to request certificates from a private CA pool, or to manage it, has no way to say so in the pool's manifest. Every other GCP kind whose resource carries an IAM policy takes `iam_members` (role plus member, granted with the provider's `*_iam_member` resource). `GcpPrivateCaPool` does not, so the grant is made outside the catalog.

## What is already done

The first half of this issue was the Certificate Manager issuance config that Google refuses unless its service agent holds `roles/privateca.certificateRequester` on the pool ("Config validation failed", measured live on 2026-11-19 on both engines). That is settled in `GcpCertManagerIssuanceConfig` itself: both modules create the Certificate Manager service agent (`google_project_service_identity` through `google-beta`, admitted in `pkg/providerparity/admissions/google-beta.yaml`; Pulumi `projects.ServiceIdentity`), grant it the requester role on the referenced pool in the pool's own project and location, and only then create the config. The permission manifest carries `privateca.caPools.getIamPolicy` and `setIamPolicy`, and the GUIDE teaches that two configs over one pool share the one binding.

## Fix

`GcpPrivateCaPool` gains `iam_members` (repeated role and member, the member a `StringValueOrRef` onto the identity kinds), realized by `google_privateca_ca_pool_iam_member` on Terraform and `certificateauthority.CaPoolIamMember` on Pulumi, with the parity, permission (`privateca.caPools.getIamPolicy` and `setIamPolicy`, conditional on the field) and doc updates the doctrine requires.

## Status

Open. The issuance-config half is done; the pool's `iam_members` companion remains.
