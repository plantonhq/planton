# A GCP Certificate Manager issuance config can't be built from the catalog alone

**Area:** the open-source GCP catalog (`catalog/gcp/`), `GcpCertManagerIssuanceConfig` and `GcpPrivateCaPool`.
**Confidence:** measured live on 2026-11-19. Both engines' creates were refused with "Config validation failed" over a DevOps-tier pool holding an enabled root authority. A hand grant of `roles/privateca.certificateRequester` to the Certificate Manager service agent was then refused as an invalid member, because the agent did not exist.

## What happens

A platform engineer wants certificates issued by their private CA through Certificate Manager. They compose a pool, an authority, an issuance config and certificates from the catalog. The issuance config is refused at create. Google requires the Certificate Manager service agent (`service-<project_number>@gcp-sa-certificatemanager.iam.gserviceaccount.com`) to hold `roles/privateca.certificateRequester` on the pool first. Google creates that agent only on request (`gcloud beta services identity create --service=certificatemanager.googleapis.com`), never when the API is turned on. No catalog kind creates the agent or grants on a CA pool, so the engineer has to leave the catalog for two steps.

The kind's GUIDE and its `ca_pool` field comment now teach this.

## Fix

The issuance config owns what it can't work without, the way `GcpBinaryAuthorizationAttestor` grants on its own note:
- the module creates the agent (`google_project_service_identity`, a google-beta resource, entered through the beta admission list) on both engines;
- it grants the agent `roles/privateca.certificateRequester` on the pool it names;
- the permission manifest gains `serviceusage.services.generateServiceIdentity` and the pool's `getIamPolicy` and `setIamPolicy`;
- then the config is created.

`GcpPrivateCaPool` separately lacks the `iam_members` companion the parity doctrine gives every resource with an IAM policy; add it in the same pass. The GCP proof lane carries `GcpCertManagerIssuanceConfig` to its session 3, beside the CA pool group (Q16), and proves the kind there.
