# BigQuery capacity and connection kinds: capabilities the console asked for that need more than text

**Area**: `catalog/gcp/gcpbigquerycapacitycommitment`, `gcpbigqueryreservation`, `gcpbigqueryreservationgroup`, `gcpbigqueryconnection`, `gcpbigquerytable`.
**Type**: feature.

## What is asked

- **A commitment's module refuses a replacing plan:** a change that replaces a commitment buys a new one while the old one cannot be deleted before its term.
- **Upstream:** the provider never sends `enforceSingleAdminProjectPerOrg` as a create query parameter, so the guard cannot be expressed.
- **A reservation uses Google's transactional `move`** when an assignee changes reservation, instead of delete and create.
- **Fields the provider lacks:** `maxSlots` and `scalingMode`, the newer job types, priority, nested groups, and the reservation's replication outputs.
- **The connection's identity in member form** (`serviceAccount:...`) as outputs beside the bare emails.
- **`GcpBigQueryTable.connection_id`** becomes a reference to the connection's `name` output instead of a plain string.

Source: the console team's notes of 2026-10-20 and 2026-10-21 (BigQuery capacity; BigQuery connection).
