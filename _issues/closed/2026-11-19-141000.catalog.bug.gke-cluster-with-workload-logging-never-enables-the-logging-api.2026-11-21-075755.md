# A GKE cluster with workload logging never enables the Cloud Logging API

**Area**: `catalog/gcp/gcpgkecluster` (both engines enable only `container.googleapis.com`)
**Type**: bug. Handed by the burn-down of every reported issue (2026-09-25, Harsha's H14-4).

## What a platform engineer sees

A `GcpGkeCluster` that turns on workload logging deploys, but its logs never arrive, because the project's Cloud Logging API is never turned on. Monitoring is the same.

## Fix

When logging or monitoring is on, both modules enable `logging.googleapis.com` (and `monitoring.googleapis.com`), the way every kind enables the APIs it uses, and the permission manifest's API group covers it. Land it with the cluster's next live proof.

## Status

Closed 2026-11-21. Fixed. Both modules enable `logging.googleapis.com` and `monitoring.googleapis.com` with the cluster (`disable_on_destroy = false`, like the container API), and the permissions manifest's API group covers them. Proven live on 2026-11-20: all three cluster scenarios deployed, updated and destroyed on both engines under an identity holding only the manifest.
