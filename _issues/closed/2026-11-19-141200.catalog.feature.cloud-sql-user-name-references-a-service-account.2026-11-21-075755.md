# A Cloud SQL IAM user can't reference the service account it is for

**Area**: `catalog/gcp/gcpcloudsqluser` (`user_name` is a plain string)
**Type**: feature. Handed by the burn-down of every reported issue (2026-09-25, `plantonhq/planton#486`).

## What a platform engineer sees

`user_name` is a plain string, so a composition hand-builds the IAM user form (`<id>@<project>.iam`) from parameters, and a wrong parameter breaks it silently.

## Fix

`user_name` accepts a value or a `GcpServiceAccount` reference, and both modules derive the IAM user form from the account's email. Close `plantonhq/planton#486` with the evidence when it ships. Land it with the Cloud SQL user's next live proof.

## Status

Closed 2026-11-21. Done. `service_account` (field 10) takes a `GcpServiceAccount` reference and both modules derive the IAM user name. Proven live on 2026-11-20: the `iam-service-account` scenario created the user under the derived name, re-planned clean and destroyed it on both engines. GitHub #486 was already closed; any comment there is the founder's to post.
