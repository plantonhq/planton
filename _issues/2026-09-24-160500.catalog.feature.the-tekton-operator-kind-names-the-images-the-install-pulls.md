# The Tekton operator kind names the images the install pulls

**Area**: catalog (`KubernetesTektonOperator` outputs)
**Type**: feature -- confirm where Tekton's images come from without reading the cluster
**Found**: 2026-09-24 while giving the kind its `image_registry` setting

## What a person sees

A person who sets `image_registry` so Tekton pulls from a mirror has no way to confirm it from the resource. The only output is `namespace`. To check that the controller, the webhooks and the images every build pod starts with come from the mirror, they need cluster access and a `kubectl` read of the Pipelines controller's image and arguments. Someone who can see the resource in Planton but not the cluster cannot tell whether the mirror is in use.

## What the product should do

1. The kind's outputs name the registry the install's Tekton images are pulled from: the mirror when `image_registry` is set, `ghcr.io` otherwise.
2. The outputs name the images the install hands every build pod (entrypoint, nop, workingdirinit, sidecarlogresults) as they will be pulled, at their digests.

## Recovery until then

Read the controller Deployment: `kubectl -n tekton-pipelines get deploy tekton-pipelines-controller -o jsonpath='{.spec.template.spec.containers[0].image} {.spec.template.spec.containers[0].args}'` names the registry for the controller and for every per-build image.
