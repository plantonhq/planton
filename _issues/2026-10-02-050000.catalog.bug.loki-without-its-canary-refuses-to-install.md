# KubernetesLoki with `canary_enabled: false` refuses to install

**Area**: `KubernetesLoki`, the `canary_enabled` field (both engines)
**Type**: bug (met live 2026-10-02 installing a monolithic Loki on R2; every mode is affected)

## What a platform engineer sees

They set `canary_enabled: false` to skip the per-node canary DaemonSet, and the deploy fails with:

```
installation failed
execution error at (loki/templates/validate.yaml:6:4): Helm test requires the Loki Canary to be enabled
```

The kind accepts the field, the plan or preview succeeds, and the failure appears only when Helm renders the chart.

## Why

The upstream Loki chart refuses to render when its Helm test (`test.enabled`, on by default) is enabled while `lokiCanary.enabled` is false, because the test reads the canary's metrics. The modules switch the canary off but leave the test on.

## Desired behavior

Turning the canary off installs cleanly on both engines: the modules switch the chart's Helm test off together with the canary, and a module test pins it on each engine. Until then, a manifest leaves `canary_enabled` at its default.
