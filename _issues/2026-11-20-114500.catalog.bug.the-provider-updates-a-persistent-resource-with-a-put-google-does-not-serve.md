# The provider updates a Vertex AI persistent resource with a PUT Google does not serve

**Area**: `catalog/gcp/gcpvertexaipersistentresource` (both modules), upstream `google_vertex_ai_persistent_resource`.
**Type**: bug, upstream.

## What a platform engineer sees

Changing a persistent resource's display name or a pool's replica count fails on apply: the provider sends the update as `PUT .../persistentResources/{id}`, Google's API serves only `PATCH` there, and the call returns an HTML 404 ("Error updating PersistentResource ... got HTTP response code 404"). Labels force replacement in the provider.

## What the catalog does

Both modules replace the resource when its display name or a replica count changes (OpenTofu `replace_triggered_by` a `terraform_data` of those values; Pulumi `ReplaceOnChanges`), so the change works, at the cost of reprovisioning the machines, and the plan shows it.

## Fix

Report it upstream (the update verb belongs in the provider's generated resource). Once the pinned provider PATCHes, the two modules drop the replace rule, and the display name and replica counts update in place again; the spec comments, README, GUIDE and the e2e second act (`expect-upgrade`) change with them.
