# KubernetesGrafana's agent reader keeps a token across an account rename, and its words name "agent teammates"

**Area:** catalog (`catalog/kubernetes/kubernetesgrafana/`)

## Current behavior

1. **A renamed account keeps the old account's token.** Changing `spec.agent_reader.service_account_name` makes the agent reader's Job create the new Viewer account, but the Job keeps the Secret's stored token when it answers at the declared generation (`iac/pulumi/module/scripts.go` and `iac/tf/scripts.tf`, the `generation = TOKEN_GENERATION && answer = 200` check). It never checks which account the token belongs to, so the Secret goes on holding the old account's token. Seen on 2026-11-14 when Planton's own hub renamed `agent-teammates` to `coding-agents`: `GET /api/user` with the stored token answered `login: sa-1-agent-teammates` until the generation was bumped.
2. **The kind's words say "agent teammates"** where they mean the coding agents a team runs: the spec and outputs proto comments (and so `reference.md` and the generated stubs), `README.md`, `GUIDE.md` ("Agent teammates through MCP"), `catalog.md`, `presets/02-persistent-team.md`, both modules' comments and output descriptions, the e2e verifier comments, and `catalog/_patterns/observability-stack.md` ("Agent teammates read the hub too").

## Expected behavior

1. The Job treats a stored token as current only when it answers **and** `GET /api/user` returns the declared account's login (`sa-<n>-<service_account_name>`); otherwise it mints a token for the declared account and revokes the rest, as a generation bump does. The old account is left in place (the module never deletes an account it did not just rename). A test pins the rename case on both engines.
2. The words say "coding agents" (or "the team's coding agents").

## Implementation plan

1. Add the login check to both scripts; keep the Job's hash inputs stable apart from the script itself (the script change re-runs the Job once on every install, which is harmless: it keeps the current token).
2. Reword every place in item 2; regenerate the kind's stubs and `reference.md`.
3. Prove it with the module tests and the kind's e2e behavioral scenario `behavioral-agent-reader` extended with a rename step.
