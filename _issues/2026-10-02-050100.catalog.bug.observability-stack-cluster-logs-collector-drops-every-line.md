# The observability-stack chart's cluster-logs collector drops every line

**Area**: `charts/kubernetes/observability-stack`, `templates/collection.yaml`, the `<env>-cluster-logs` DaemonSet collector
**Type**: bug (found 2026-10-02: the same configuration, run live on a GKE cluster, failed every line until fixed; the catalog's `01-cluster-logs-to-loki` preset is fixed in the commit that files this)

## What a platform engineer sees

Their Loki receives nothing from the cluster, and the collector's own log repeats:

```
operator 'container' has 'add_metadata_from_filepath' enabled, but the log record attribute 'log.file.path' is missing. Perhaps enable the 'include_file_path' option?
```

## Why

The filelog receiver records a line's file path only with `include_file_path: true`, and the `container` operator needs that path to know the pod, namespace and container. Two more gaps in the same configuration:
- The checkpoint volume is mounted, but no `file_storage` extension or receiver `storage` uses it, so a restarted collector keeps no offsets.
- The collector reads its own log files, echoing every export error back into the stream it is failing to send.

## Desired behavior

The chart's cluster-logs collector ships every container's lines, keeps its offsets and its outgoing queue on the node, and never reads itself, as the fixed preset does. The chart's kind-cluster e2e asserts that a pod's log line arrives in Loki.
