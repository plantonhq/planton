# GCP AI kinds: capabilities the console asked for that need more than text

**Area**: `catalog/gcp/gcpvertexaiagentengine`, `gcpvertexaimodelgardendeployment`, `gcpcolabruntimetemplate`, `gcpcolabruntime`, `gcpcolabschedule`, `gcptpuvm`, `gcptpuqueuedresource`, `gcpdocumentaiprocessor`.
**Type**: feature.

## What is asked

The console team built every screen of these kinds from the released catalog and asked for what the catalog could not carry. The asks a text or rule fix settled have landed; these need a new output, a new arm, a module change or an upstream provider change:

- **Outputs the provider does not export yet:** Document AI's processor state and the version answering now; the queued resource's state; Model Garden's dedicated endpoint DNS name; a Colab Enterprise console URL for the template, runtime and schedule. Each lands once the provider exports it, never faked.
- **A "latest" Colab image** arm on the runtime template.
- **Replace triggers** for a runtime template's idle timeout, end-user credentials and Secure Boot, and for a schedule's notebook edits: today a change is never sent, and Pulumi cannot see an end-user-credential or Secure Boot change because the provider suppresses it.
- **Upstream:** a `force` delete on the TPU queued resource (the provider sends none, so a request whose nodes are up cannot be destroyed without `gcloud --force`); in-place external IP changes on a TPU VM.
- **Parity records:** Pulumi serves the Agent Engine and Model Garden from Google's v1beta1 surface; the parity files should record it.

Source: the console team's notes of 2026-10-26, 2026-10-27 and 2026-10-28 (agent and model runtimes; Colab; TPU and Document AI).
