# The operator's bundled components take an image source

**Area**: operator (`api/v1/planton_platform_types.go`, the components the operator installs beside Planton's own)
**Type**: feature -- image overrides for the third-party components, beside `spec.imageRegistry` for Planton's own images
**Found**: 2026-09-24 while moving a self-hosted install's image pulls to a Google Artifact Registry mirror and cache

## What a person sees

`spec.imageRegistry` moves the control plane, console, and runner to a mirror with one value. Everything else the operator installs still pulls from its upstream, and no field changes that: the PostgreSQL operator and the PostgreSQL image, its backup plugin, Temporal, OpenFGA, OpenBao, Valkey, Neo4j. On a cluster whose route to ghcr.io or Docker Hub is slow or rate-limited, or an air-gapped one, the install moves only part of the way. The first boot then waits on exactly the components everything else depends on: Postgres first, then OpenBao and Temporal behind it.

## What the product should do

1. The platform resource accepts an image source for its bundled components: a registry root, or a per-component repository where one root cannot hold them all. Each component then pulls from it at the version the operator pins.
2. Empty keeps each component's upstream, exactly as today.
3. The platform's status names the image each component runs, so a person confirms the mirror is in use from `kubectl get plantonplatform` alone.

## Recovery until then

Pull the bundled components from their upstreams. On a slow route, a stalled first boot recovers on its own once the database image arrives; the components that time out while waiting are re-applied once it is up.
