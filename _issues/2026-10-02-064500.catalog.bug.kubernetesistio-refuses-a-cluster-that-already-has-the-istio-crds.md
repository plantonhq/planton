# KubernetesIstio refuses to install where KubernetesIstioBaseCrds already applied the Istio CRDs

**Area**: `KubernetesIstio`, the Pulumi module's CRD apply; the e2e harness's Istio prerequisite chain
**Type**: bug (met 2026-10-02 running the mesh-backed e2e scenarios on the kind cluster)

## What a platform engineer sees

On a cluster where `KubernetesIstioBaseCrds` is installed (the CRDs-only kind for using the policy APIs without a mesh), they add `KubernetesIstio` to get the full mesh. The Pulumi deploy fails:

```
kubernetes:apiextensions.k8s.io/v1:CustomResourceDefinition proxyconfigs.networking.istio.io creating failed
customresourcedefinitions.apiextensions.k8s.io "proxyconfigs.networking.istio.io" already exists
```

A second attempt, after the first one's cleanup, fails the same way on the `istio-system` Namespace (`namespaces "istio-system" already exists`).

The kind's own documentation (`spec.istiod`'s CRD note) promises the opposite: the CRDs are applied by server-side apply outside the Helm release so they are "co-ownable by both kinds, making that migration a plain redeploy".

## Where it bites today

The e2e harness installs `KubernetesIstioBaseCrds` for every Istio policy kind (each declares it as a registry prerequisite) and then the scenario's `KubernetesIstio` prerequisite, so both mesh-backed behavioural scenarios fail before their checks run:

- `catalog/kubernetes/kubernetesauthorizationpolicy/e2e/scenarios/behavioral-deny.yaml`
- `catalog/kubernetes/kubernetesrequestauthentication/e2e/scenarios/behavioral-jwt.yaml` (a stranger's token 401, no token 403 through the paired ALLOW policy, the trusted token 200, and the 401 released once the check is destroyed)

Reproduce: `go test -tags=e2e -timeout=30m -v -count=1 -run 'TestKubernetesAuthorizationPolicy_Pulumi/behavioral-deny' ./e2e/`.

## Desired behavior

`KubernetesIstio` installs over existing Istio CRDs and an existing `istio-system` namespace, as its documentation states, on both engines, with a module test that pins the upgrade from the CRDs-only kind. Then both behavioural scenarios run to their checks.
