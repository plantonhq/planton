# GCP Identity Platform Tenant

Creates one Identity Platform TENANT — an isolated user pool with its own sign-in configuration and identity providers, inside a project whose Identity Platform allows tenants. Tenants are how one project serves multiple customer organizations (B2B SaaS) with fully separated users, providers, and policies; each tenant's IdP client secrets are handled as managed secrets end to end.

## What Gets Created

When you deploy this Infra Component, the IaC module provisions:

- **Tenant** -- an `identity_platform_tenant` with display name, sign-up switches, kill switch, and client permissions (the tenant ID is server-generated — read the `tenant_id` output)
- **Tenant-scoped IdP configs** -- one composed resource per entry in `defaultSupportedIdps`, `oauthIdpConfigs`, and `inboundSamlConfigs`, scoped to this tenant only
- **Identity Toolkit API enablement** -- `identitytoolkit.googleapis.com` enabled in the target project (never disabled on destroy)

## Before You Deploy

### Planton Setup

- **GCP Provider Connection** -- an active connection in the Connect module with credentials for the target GCP project. Map it as the default for your environment, or specify it explicitly when creating the Infra Component.
- **IdP credentials** (when configuring providers): each provider's `clientId`/`clientSecret` comes from that provider's own developer console, supplied as managed secrets.

### GCP Project

- **The project's GcpIdentityPlatformConfig must set `multiTenant.allowTenants: true`** — the tenant API rejects creation otherwise.
- **IAM**: the deploying identity needs `roles/identityplatform.admin` or broader.

## Deploy

### Console

Open the deployment store, find **GCP Identity Platform Tenant**, and click **Deploy**. The creation wizard walks you through the target project, the tenant's display name and sign-in switches, and the tenant-scoped identity providers. Start from the **B2B Tenant** preset in the [Presets](#presets) tab for the most common shape.

### CLI

Create a manifest and apply it:

```yaml
apiVersion: gcp.planton.dev/v1alpha1
kind: GcpIdentityPlatformTenant
metadata:
  name: acme-corp-tenant
  org: acme-corp
  env: prod
spec:
  displayName: acme-corp
  allowPasswordSignup: true
  deletionPolicy: PREVENT
```

```shell
planton apply -f tenant.yaml
```

This creates an isolated user pool for one customer organization; the server-generated `tenant_id` output is what client SDKs set as `tenantId` to scope sign-in to this tenant. An Infra Job tracks the provisioning in real time.

### InfraChart

When deploying as part of a multi-resource environment, the tenant references its project via ValueFromRef:

```yaml
spec:
  projectId:
    valueFrom:
      kind: GcpProject
      name: app-project
      fieldPath: status.outputs.project_id
  displayName: acme-corp
```

The InfraPipeline deploys the project (and its Identity Platform config with `allowTenants` armed) first, then creates the tenant.

## Key Configuration

These are the most important decisions when configuring a tenant. Explore the full field reference in the [API Explorer](#api-explorer) tab.

**Display name** -- the only naming input; the tenant's resource ID is generated by GCP at create time and read from the `tenant_id` output.

**Sign-in switches** -- `allowPasswordSignup` and `enableEmailLinkSignin` control first-party sign-in; `disableAuth` is the tenant-wide kill switch (nothing authenticates, existing sessions stop refreshing).

**Identity providers** -- the three lists mirror the project-level shapes with the API's own tenant-level differences: OIDC `displayName` is required and there is no `responseType`; SAML `spConfig` (both `callbackUri` and `spEntityId`) is required.

**Deletion policy** -- ONE switch governs the tenant AND its composed IdP configs. `DELETE` removes every user account in the tenant, unrecoverable — use `PREVENT` for production tenants.

## Outputs and Dependencies

### What This Kind Consumes

| Dependency | Field | ValueFromRef Path |
|------------|-------|-------------------|
| **GcpProject** (optional) | `projectId` | `status.outputs.project_id` |

### What This Kind Provides

After provisioning, `status.outputs` contains values that downstream Infra Components can consume via ValueFromRef:

| Output | Description | Common Downstream Use |
|--------|-------------|----------------------|
| `tenant_id` | The server-generated tenant ID | Client SDK `tenantId` wiring; tenant-scoped API calls |
| `tenant_name` | `projects/{project}/tenants/{tenant_id}` | Referencing the tenant in tooling |

## Common Patterns

Browse the [Presets](#presets) tab for ready-to-deploy configurations.

**B2B tenant** -- one tenant per customer organization with password sign-up and `PREVENT` teardown protection. Start from the **B2B Tenant** preset.

**SSO tenant** -- a tenant whose customer brings their own SAML IdP; users authenticate against the customer's directory. Start from the **SSO Tenant** preset.
