# GcpIdentityPlatformTenant - Terraform Module

This Terraform module provisions an Identity Platform tenant (`google_identity_platform_tenant`) plus one composed resource per identity provider the spec lists (`google_identity_platform_tenant_default_supported_idp_config`, `google_identity_platform_tenant_oauth_idp_config`, `google_identity_platform_tenant_inbound_saml_config`). It is the Terraform-side implementation of the Planton `GcpIdentityPlatformTenant` resource kind and has feature parity with the Pulumi module.

## Overview

A tenant is an isolated user pool inside a project whose Identity Platform config enables `multi_tenant.allow_tenants` (the `GcpIdentityPlatformConfig` kind). The tenant's resource ID is generated by GCP at create time — `display_name` is the only naming input — and flows to the IdP configs through the created resource's name. The spec's ONE `deletion_policy` fans out to the tenant and every composed IdP config. The module runs on the plain `google` provider — every modeled field is GA on the pinned 8.x line.

## Usage with Planton CLI

```shell
planton tofu init --manifest ../../e2e/manifest.yaml
planton tofu plan --manifest ../../e2e/manifest.yaml
planton tofu apply --manifest ../../e2e/manifest.yaml --auto-approve
planton tofu destroy --manifest ../../e2e/manifest.yaml --auto-approve
```

Credentials are provided via stack input (by the CLI), not in the manifest `spec`. Manifest file: `../../e2e/manifest.yaml`.

## Direct Terraform Usage

```bash
cd catalog/gcp/gcpidentityplatformtenant/iac/tf
terraform init
terraform plan -var-file=terraform.tfvars.json
terraform apply -var-file=terraform.tfvars.json
```

## Variables

| Name | Description | Default |
|------|-------------|---------|
| `metadata` | Resource metadata (name, labels, etc.) | — |
| `spec` | GcpIdentityPlatformTenant spec | — |

The `spec` object includes: `display_name` (required), `allow_password_signup`, `enable_email_link_signin`, `disable_auth` (the kill switch), `client_permissions`, the three tenant IdP lists (`default_supported_idps`, `oauth_idp_configs` with tenant-required `display_name` and no `response_type`, `inbound_saml_configs` with tenant-required `sp_config`), `project_id` (empty falls back to the provider default project), and `deletion_policy` (DELETE/PREVENT/ABANDON — one switch for the tenant and its IdP configs).

## Outputs

| Name | Description |
|------|-------------|
| `tenant_id` | The server-generated tenant ID (what client SDKs set as tenantId) |
| `tenant_name` | `projects/{project}/tenants/{tenant_id}` |
