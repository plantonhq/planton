# KubernetesAgentSubstrateSandboxConfig Terraform Module

This module creates one cluster-scoped Agent Substrate `SandboxConfig` through `kubectl_manifest` (alekc/kubectl). It is generated by `planton tofu generate-module KubernetesAgentSubstrateSandboxConfig`; never edit its `.tf` files by hand, regenerate them. A drift test in `pkg/iac/tofu/generators` fails when the committed files and the generator disagree.

The converter hands the module the manifest's spec with its upstream keys, null fields pruned, and each architecture's asset files written as the bare map upstream defines (the manifest's `entries` wrapper removed). The module routes the envelope to the object's metadata (`name`, and the spec's `labels` and `annotations` under Planton's identity labels) and passes everything else to the custom resource's spec verbatim.

## Prerequisites

- Agent Substrate on the cluster (see the `KubernetesAgentSubstrate` kind): the SandboxConfig definition and the `sandboxconfig-assets` admission policy. `kubectl_manifest` needs no cluster connection at plan time, so the config can be planned before the definition exists.

## Usage

```bash
planton tofu apply --manifest sandbox-config.yaml
```

## Outputs

| Output | Description |
|--------|-------------|
| `sandbox_config_name` | Name of the created SandboxConfig (the spec's `name`), which worker pools name |
| `sandbox_class` | The config's class, which the worker pool's `sandbox_classes` entry must equal |

## Import

An existing SandboxConfig imports with the ID `ate.dev/v1alpha1//SandboxConfig//<name>` (see `../import-map.yaml`).
