# Argo CD

Deploys Argo CD — the declarative GitOps continuous-delivery engine for Kubernetes — from the official `argo-cd` Helm chart. Argo CD watches Git repositories and keeps cluster state converged with what the repositories declare; this component installs and shapes the control plane itself at chart grain: every Argo CD component individually sized, the Redis cache as an explicit three-way choice, SSO and RBAC as first-class blocks, and an honest first-login story. The grain is deliberate: **this kind deploys the control plane; declaring what it deploys is not its job.** Once Argo CD runs, Applications, AppProjects and ApplicationSets are plain custom resources — declare them via KubernetesManifest, a chart, or Argo CD's own UI/CLI. Exposure is composed too: the server stays ClusterIP, and Ingress or Gateway kinds publish it over the exported `server_service` handle.

## What Gets Created

When you deploy this Infra Component, the IaC module provisions:

- **Helm release** (official `argo-cd` chart, default pin `10.2.1`, named `metadata.name`) — the API/UI **server**, the **application controller** (the reconciliation engine), the **repo server** (clones repositories and renders manifests — the first kind to saturate as syncs grow), the **ApplicationSet controller**, and three toggleable components with different chart defaults: **notifications** (on), **dex** (on — inert until connectors are declared), and the **commit server** (off — only hydrated-manifest workflows need it)
- **A Redis cache** matching the declared arm — the chart's single-pod bundled cache when nothing is declared, a 3-node Sentinel HA cluster behind HAProxy, or no Redis at all when an external endpoint is referenced. Whatever the arm: Redis here is a **disposable cache** — losing it costs a re-sync, never state; everything real lives in the CRs and Git history
- **The Argo CD CRDs** (Application, AppProject, ApplicationSet) — installed and kept on uninstall by default; see the one-way door below
- **Kubernetes Namespace** — created only when `createNamespace` is true; otherwise the namespace must already exist
- **The `argocd-initial-admin-secret` Secret** — generated by Argo CD itself at first start with the admin password (when the local admin is enabled); its name and a ready-made port-forward command land in the outputs

## Before You Deploy

### Planton Setup

- **Kubernetes Provider Connection** — an active connection in the Connect module with credentials for the target cluster.

### Kubernetes Cluster

- **Cluster-scoped permissions** — Argo CD manages applications across namespaces; the install creates CRDs, ClusterRoles and ClusterRoleBindings.
- **metrics-server** — only if you enable autoscaling on the server or repo server (the HPAs meter CPU requests).
- **At least three schedulable worker nodes** — only for the HA Redis arm; its pods carry a required anti-affinity and stay Pending on smaller clusters.
- **kube-prometheus-stack** — only if you set `serviceMonitorsEnabled` (the ServiceMonitor objects need the Prometheus Operator CRDs to admit).

## Deploy

### Console

Open the deployment store, find **Argo CD**, and click **Deploy**. The creation wizard walks you through namespace placement, the chart pin, access (the local admin tri-state and the public domain), each component at chart grain, the Redis three-arm choice, SSO, RBAC, repositories, the CRD lifecycle (with the one-way-door warning), metrics, the air-gap image path, placement, and the Helm-values escape hatch. Start from the **Dev GitOps preset** in the [Presets](#presets) tab.

### CLI

Create a manifest and apply it:

```yaml
apiVersion: kubernetes.planton.dev/v1alpha1
kind: KubernetesArgocd
metadata:
  name: dev-argocd
  org: acme-corp
  env: dev
spec:
  namespace:
    value: dev-argocd
  createNamespace: true
```

```shell
planton apply -f argocd.yaml
```

This near-empty spec is a complete GitOps control plane at chart defaults. First login: read the generated password from the `argocd-initial-admin-secret` Secret (the exact name and a `kubectl port-forward` command are in the outputs), sign in as `admin`, and point your first Application at a repository. An Infra Job tracks the provisioning in real time.

### InfraChart

Compose Argo CD behind its namespace with a reference:

```yaml
spec:
  namespace:
    valueFrom:
      kind: KubernetesNamespace
      name: gitops-namespace
      fieldPath: spec.name
  createNamespace: false
```

The InfraPipeline creates the namespace first, then deploys the control plane into it.

## Key Configuration

These are the most important decisions when configuring an Argo CD control plane. Explore the full field reference in the [API Explorer](#api-explorer) tab.

**The first-login story is honest.** With the local admin enabled (the default), Argo CD generates the admin password once per install into the fixed-name `argocd-initial-admin-secret` Secret — one generated-password install per namespace. Rotation is change-then-delete: change the password via the CLI, then delete the Secret. `adminEnabled` is a genuine tri-state: unset defers to the chart (admin on), explicit `false` retires the local admin — **only after SSO works**, or the UI locks everyone out.

**TLS terminates at the composed edge.** The server ships a self-signed listener — fine for a port-forwarded dev loop. When real exposure is composed (an Ingress or a Gateway kind over the exported `server_service`), set `server.insecure: true` so the edge terminates TLS; leaving the self-signed listener behind a proxy double-encrypts and breaks gRPC CLI traffic. Set `domain` at the same time — SSO redirect URLs and CLI login hints embed it.

**Components scale for different reasons.** The repo server saturates first — every sync clones and renders there; scale it (replicas or an autoscaler) when sync latency grows. Controller replicas are **shards across target clusters**, not load-balanced copies — sharding a single-cluster install buys nothing. Server and repo server both take an optional autoscaling block (min/max default 1/5, max ≥ min enforced); a CPU HPA without a CPU request never scales.

**The Redis choice is a three-arm decision.** Declare nothing and the chart runs its single-pod bundled cache — right for dev and small installs. The `ha` arm runs a 3-node Sentinel cluster (replicas ≥ 3; remember the anti-affinity needs three nodes). The `external` arm points at an endpoint you operate — its `host` composes by reference from a KubernetesValkey's exported service; optional credentials ride a named Secret, never the manifest.

**SSO is direct OIDC, dex connectors, or deliberately both.** The `oidc` block does provider-native OIDC: name, issuer, client ID, and the client secret as a **name + key reference** to an existing Secret — the credential never rides the manifest, and the referenced Secret must carry the `app.kubernetes.io/part-of: argocd` label or Argo CD refuses to read it (compose it from KubernetesSecret or KubernetesExternalSecret). Leave the reference empty for a public-client PKCE flow. `dexConfig` carries dex connector YAML for protocols OIDC alone cannot speak (SAML, LDAP, GitHub teams) — it requires the dex component enabled, and its secrets use Argo CD's `$<secret-name>:<key>` indirection, never inline. Configuring both puts two SSO buttons on the login screen — legitimate during a migration, a misconfiguration otherwise.

**RBAC defaults to invisible.** An empty `policyDefault` means authenticated users see nothing until a `policyCsv` rule grants access — the safe default for a shared instance; `role:readonly` is the friendlier alternative. `scopes` defaults to `[groups]`, mapping the identity provider's group claims into policy subjects. `execEnabled` opens an interactive shell into live containers through the API server — a deliberate grant paired with an RBAC `exec` rule, never a default.

**Repositories here are public/anonymous only.** The `repositories` repeater registers public Git/Helm sources. Credentialed repositories are composed as labeled Secrets (`argocd.argoproj.io/secret-type: repository`) next to the install — credentials never transport through this spec.

**THE CRD ONE-WAY DOOR:** `crds.keep` defaults to `true` for a reason — flipping it to `false` means uninstalling this release **deletes every Application, AppProject and ApplicationSet in the cluster**, not just the control plane. And the ownership trap on `crds.install`: CRDs installed by one release cannot be adopted by a second — a reinstall that skips them must set `install: false` or the upgrade collides.

**`reconciliationTimeout`** controls how often Argo CD polls repositories (chart default `180s`; empty defers). Lower means faster syncs but more repo-server and Git load; webhook-driven setups can raise it instead.

**`helmValues` merges last** — the escape hatch for chart surface beyond the typed fields (notification templates and triggers, per-kind env, ingress annotations the chart renders itself). Anything here silently overrides the typed fields on every deploy; never put secrets in it.

**Air-gap path:** the `image` block re-points repository/tag/pull-secret for the Argo CD image that serves all core components; dex and the bundled Redis pull their own chart-default images — re-point those via `helmValues` when mirroring everything.

## Outputs and Dependencies

### What This Kind Consumes

| Dependency | Field | ValueFromRef Path |
|------------|-------|-------------------|
| **KubernetesNamespace** | `namespace` | `spec.name` |
| **KubernetesValkey** | `redis.external.host` | `status.outputs.service` |

The OIDC client secret, external-Redis credentials, and image pull secrets are referenced by Secret NAME (plain strings), not ValueFromRef — compose those Secrets next to the install.

### What This Kind Provides

After provisioning, `status.outputs` contains values that downstream Infra Components can consume via ValueFromRef:

| Output | Description | Common Downstream Use |
|--------|-------------|----------------------|
| `namespace` | Namespace Argo CD runs in | Composing labeled Secrets (OIDC, repositories) next to the install |
| `server_service` | The API/UI server Service name | Ingress/Gateway exposure |
| `server_kube_endpoint` | Cluster-internal FQDN of the server | In-cluster API clients |
| `initial_admin_secret_name` | The generated-password Secret (`argocd-initial-admin-secret`) | The first login: `kubectl get secret … -o jsonpath='{.data.password}' \| base64 -d` |
| `port_forward_command` | Copy-paste `kubectl port-forward` for the server | Local access before exposure is composed |

## Common Patterns

Browse the [Presets](#presets) tab for ready-to-deploy configurations.

**Dev loop / first contact** — the smallest useful Argo CD: chart defaults end to end, first login through the generated-password Secret and the exported port-forward command. Start from the **Dev GitOps preset**.

**A team's shared instance** — direct OIDC with the client secret as a labeled-Secret reference, read-only-by-default RBAC with a platform admin group, TLS handed to the composed edge, and the local admin retired (`adminEnabled: false`) once SSO carries the load. Start from the **Team SSO + RBAC preset**.

**Hundreds of Applications** — server and repo server on HPAs with explicit CPU requests, a memory-sized controller, the HA Sentinel Redis arm, faster reconciliation, and ServiceMonitors for the monitoring stack. Start from the **Scaled platform preset**.

## Works With

- [**Kubernetes Namespace**](/infra-catalog/kubernetes-namespace) — referenced placement; the InfraPipeline orders namespace-first.
- [**Kubernetes Ingress**](/infra-catalog/kubernetes-ingress) — exposes the UI/API over the exported `server_service` handle (set `server.insecure` and `domain` when composing); [**Kubernetes HTTPRoute**](/infra-catalog/kubernetes-http-route) is the Gateway API alternative.
- [**Valkey**](/infra-catalog/kubernetes-valkey) — the external Redis arm references its exported service endpoint.
- [**Kubernetes Secret**](/infra-catalog/kubernetes-secret) — composes the labeled OIDC client-secret Secret and credentialed-repository Secrets next to the install; [**External Secret**](/infra-catalog/kubernetes-external-secret) does the same from an external store.
- [**kube-prometheus-stack**](/infra-catalog/kubernetes-kube-prometheus-stack) — scrapes the per-kind ServiceMonitors when `serviceMonitorsEnabled` is set.
- [**Kubernetes Manifest**](/infra-catalog/kubernetes-manifest) — declares Applications/AppProjects/ApplicationSets once the control plane runs.
