# KubernetesAgentSubstrateWorkerPool Terraform Module

This module creates one namespaced Agent Substrate `WorkerPool` through `kubectl_manifest` (alekc/kubectl). It is generated by `planton tofu generate-module KubernetesAgentSubstrateWorkerPool`; never edit its `.tf` files by hand, regenerate them. A drift test in `pkg/iac/tofu/generators` fails when the committed files and the generator disagree.

The converter hands the module the manifest's spec with its upstream keys, null fields pruned, 64-bit integers as numbers, and references resolved to plain strings (the worker image, the SandboxConfig, the ServiceAccount and the PriorityClass). The module routes the envelope to the object's metadata (`namespace`, and the spec's `labels` and `annotations` under Planton's identity labels) and passes everything else to the custom resource's spec verbatim.

## Prerequisites

- Agent Substrate on the cluster (see the `KubernetesAgentSubstrate` kind). `kubectl_manifest` needs no cluster connection at plan time, so the pool can be planned before the definition exists.
- The target namespace (see `KubernetesNamespace`), enforcing no Pod Security level.

## Usage

```bash
planton tofu apply --manifest worker-pool.yaml
```

## Outputs

| Output | Description |
|--------|-------------|
| `worker_pool_name` | Name of the created WorkerPool (equals `metadata.name`), which its worker Deployment shares |
| `namespace` | Namespace the WorkerPool and its workers run in |

## Import

An existing WorkerPool imports with the ID `ate.dev/v1//WorkerPool//<name>//<namespace>` (see `../import-map.yaml`).
