# catalog/_pricing — Price Books, Derivations, and Generated Estimates

This tree is the ONE home for dollar figures in this repository. Prices are volatile, so they live here — pinned, source-dated, and machine-refreshable — instead of beside every kind. Documentation prose everywhere else teaches cost DRIVERS (what bills, which choices are the cost cliffs), never dollar amounts: the price-provenance gate (`pkg/priceprovenance`) fails CI on a hand-typed price in any catalog or chart markdown outside this tree.

## The five subtrees, and the one-home-per-quantity law

A kind's quantities have exactly one home, in one of three forms:

- **`derivations/`** — machine-executable rules turning ANY manifest's spec values into metered quantities and price choices. Configurations whose cost is unknowable refuse with the reason, never a guess.
- **`capacity/`** — the cluster-capacity twin for Kubernetes workload kinds: what the workload RESERVES, stated as capacity, never dollars (cluster-capacity kinds create no cloud SKU).
- **`models/`** — hand-authored per-preset quantity assumptions for kinds not yet derived.

And two trees the above resolve against or produce:

- **`pricebook/`** — one pinned price book per provider: every unit price with its source URL and retrieval date. Entries with a machine selector refresh from the provider's public price API via `make generate-price-book`.
- **`estimates/`** — GENERATED by `make generate-cost-estimates`, never edited: for derived kinds by replaying every preset manifest through the rules, for modeled kinds by joining the model with the book. Every line cost and total is computed exactly.

## The gates

The `lint.catalog-data` gate re-computes every figure and holds the committed estimates byte-identical to their inputs — a disagreement between rules or model, price book, and a kind's `cost.yaml` fails CI. The `lint.price-provenance` gate keeps prose price-free everywhere else. Together they make the platform's cost claims deterministic: the same manifest produces the same number, every time, and every number traces to a pinned, dated source.

## Fixing a price or an estimate

A stale unit price is refreshed in `pricebook/` (via the generator where a selector exists — the source URL and retrieval date travel with it). A wrong quantity is fixed in the kind's derivation, capacity derivation, or model — then estimates regenerate. Never edit anything under `estimates/` by hand, and never write a dollar figure in a README, guide, catalog page, or preset doc — teach the driver and let the generated estimate carry the number.

The kind anatomy these files plug into is defined once, in [architecture/catalog-kind.md](../../architecture/catalog-kind.md).
